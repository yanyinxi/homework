后端系统设计作业
目标
设计并实现一套视频素材数据的存储与查询服务，包含数据库设计和只读 API 两个部分。
Part A · 数据库设计
允许使用的技术：ElasticSearch（NoSQL）或 PostgreSQL（SQL）二选一，说明选择原因。

参考数据： 
doc/素材数据集1.xls
doc/素材数据集2.xls
doc/素材数据集3.xls

设计一套 schema，能够统一存储上述数据集中的素材记录。schema 需包含字段类型定义、索引策略，并说明设计依据
至少导入一份数据集 
附加目标：将三份数据集全部导入同一 schema
验证以下查询可以正常执行，并导出查询结果（JSON 或截图均可）： 
统计审核状态为"已通过"的素材中，各上传人的平均文件大小
按标签统计素材数量，列出数量最多的前 5 个标签
一条你认为有价值的自选查询，并说明业务意义
提供所选 schema / Index Mapping，并用文档说明设计决策（PDF 格式即可）



Part B · 只读 API
基于 Part A 中已导入数据的数据库，实现以下接口：
通过 GET 请求列出素材数据 
支持按一个或多个字段过滤（例如 /assets?status=approved&uploader=张三 或 /assets?file_size[lte]=524288000）
支持按一个或多个字段排序（例如 /assets?sort=uploaded_at:desc,file_size:asc）
通过 GET 请求获取单条记录（例如 /assets/:id） 
附加目标：支持稀疏字段集返回（例如 /assets/:id?fields=title,status,uploader）
